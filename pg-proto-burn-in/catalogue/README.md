# Protocol coverage catalogue

`generated-v1.json` snapshots the stable IDs generated by the six protocol
grammars. `supplemental-v1.json` is the checked-in authority for semantic cases
which the grammar alone cannot enumerate. `catalogue-lock-v1.json` locks their
union so removing or renaming either kind of ID requires a migration.

`migrations-v1.json` accepts reviewed `rename`, `split`, `merge`, and `retire`
records. Every record has a unique `id`, non-empty `from` and/or `to` cardinality
appropriate to its kind, a `reason`, and a `review` reference. Sources must exist
in the lock, destinations must exist in the live catalogue, and every removed ID
must occur exactly once as a source.

`exemptions-v1.json` is the only authority allowed to exempt coverage. Each
record contains:

```json
{
  "id": "an.exact.catalogue.id",
  "reason": "why direct evidence is unavailable",
  "postgres_versions": ["14-18"],
  "scripted_coverage": "optional.catalogue.substitute",
  "owner": "maintaining-team",
  "reviewed_by": "reviewer",
  "review": "issue-or-ADR-reference",
  "expires_on": "2026-12-31"
}
```

The catalogue command requires an explicit `--as-of YYYY-MM-DD`, rejects expired
or malformed records, and does not accept exemptions claimed by input artifacts.
Changing any registry schema requires a new version rather than silently
reinterpreting existing evidence.
